# 部署与常见问题

[返回总[[小画画像机器人/README]]览](../README.md) · [下一章：实验验证](validation.md)

以下入口对应当前 Windows 工程。文档包本身不能启动机器人程序；需要完整应用源码、相机/机器人环境以及相应模型资源。

## 本地安装和启动

1. 将应用工程放在本机较短的目录中，例如 `C:/PaintingRobot/`。U 盘用于转移文件，运行环境在目标电脑重新建立，避免把另一台机器的虚拟环境当作可直接移植的安装包。
2. 安装标准 64 位 CPython 3.12～3.14，包含 Tkinter 和 Python launcher。核心安装脚本会检查解释器兼容性。
3. 双击 `SETUP_FACE_WINDOWS.bat`，建立或修复 `.venv-face314`，安装 `requirements.txt`。目录名不要求解释器必须是 3.14。
4. 需要抠图时，双击 `SETUP_MATTING_WINDOWS.bat`，安装扩展依赖并准备本地抠图资源。第一次下载耗时取决于网络；离线机器需提前配置完整模型资源。
5. 使用云端自由改图或 skill 时，双击 `CONFIGURE_PAINTING_API.bat` 配置密钥与接口。离线二值化不需要API密钥。
6. 双击 `START_FACE_WINDOWS.bat`。主程序启动 Tk 工作台和 localhost 图片准备网页。

入口调用关系为 `main.py → GUI.py → FaceDrawingApp`。依赖包括 NumPy、SciPy、opencv-contrib-python、Pillow、requests；`opencv-contrib-python` 中的 `ximgproc` 是细化步骤所需模块。抠图另需 PyTorch、Transformers 等依赖。

核心启动可不依赖 Codex、Obsidian 或浏览器中的 file 页面。`frontend/index.html` 负责页面结构，`app.js` 负责事件与服务调用，`style.css` 负责布局样式。直接双击 HTML 只显示静态页面，不会创建 Python HTTP 服务。

## ABB 侧的前提

必须加载与客户端兼容的 RAPID 网络接收任务、运动任务和共享数据定义；TCP 端口、目标地址及网络连通性匹配，控制器允许执行这些任务。当前发送依赖 START 的即时处理、与 Python 阈值一致的 RAPID 可用缓冲容量、Stamp 和运动状态查询。容量调整后须同步两端定义及检查；客户端目前不会自动发现控制器容量。

工程中的 `robot_origin_code/` 保留运动与公共模块参考；部署还必须取得对应的网络接收私有模块及完整任务配置。仅复制两个参考 `.mod` 文件不能视为完成控制器安装。实验室现有控制器备份应由设备负责人保管，公开仓库不默认发布整机备份。

工具、纸面工作坐标、落笔/抬笔高度、拍照位、准备位、离纸位和可选盖章位需要现场核对。当前路径校验仅支持 A3 与 1.5 mm 笔宽；换纸张、工具或工作面后需要更新标定和相关约束。

## API 与本地功能配置

| 用途 | 实现方式 |
| --- | --- |
| 前端自由文本改图 | 通过 API 编辑当前图片 |
| 勾选 skill 后结构整理 | 通过 API 配合 skill 规则整理结构 |
| 固定语音素材生成记录 | 预先通过 API 生成，运行时本地播放 |
| 本地抠图 | 本地推理，输出前景透明度 |

`AiRepaint.py` 负责 API 适配，并包含不同编辑入口。调整接口配置时，应检查实际调用入口、请求格式和返回结果处理。

API 配置由本机私有配置文件 `.painting-api.json` 或对应运行环境提供，本机配置优先。访问凭据、接口地址与调用权限应相匹配；具体调用配置由部署环境维护。不要把实际密钥放入 README、截图、日志附件或 Git 提交。

## 超时为什么可能提前报错

当前本地 `AiRepaint.py` 的默认值如下。其他电脑若做过手动修改，应以正在运行的那份代码为准。

| 参数 | 当前值 | 意义 |
| --- | --- | --- |
| 结构提交 POST 连接超时 | 15 秒 | 建立连接的等待上限 |
| `structure_submit_timeout` | 180 秒 | 结构提交等待 HTTP 回应的读取上限 |
| `request_timeout` | 60 秒 | 普通请求和下载等阶段的超时 |
| `task_timeout` | 600 秒 | 取得任务编号后等待生成任务的总轮询上限 |
| `poll_interval` | 3 秒 | 任务查询间隔 |

只把提交读取上限改为 300 秒，不会把所有连接错误都推迟到 300 秒。DNS、代理、TLS、网络连接中断或服务器明确返回错误可以更早失败；“上限”也不是必须等待这么久。`ConnectionError` 与 `ReadTimeout` 是不同情况。

已取得任务编号时可查询任务状态；提交时连接中断、尚未取得任务编号时，客户端不能确认云端是否已接收。当前程序不会自动重复提交这类结构请求，以免重复生成与计费。反复手动点击能偶尔成功，说明值得检查该电脑的网络、代理与请求链路，但不能单凭此现象排除客户端配置问题。

## 其他排查

| 现象 | 优先核对 |
| --- | --- |
| Windows 解压提示路径太长 | 缩短顶层解压路径；项目打包不携带虚拟环境和大量 Python 缓存 |
| skill 结果添加不存在的眼镜 | 对照原图与结构图；检查正在运行的规则文件和结构缓存键，避免无条件配饰提示 |
| 最终人物在纸上偏小 | 检查有效墨迹裁边、纸面边距、保持比例后的布局，区分显示缩放和物理映射 |
| 采样指令数量过多 | 检查初始拟合恢复代码是否更新、是否存在异常曲线或过长连续路径 |
| 机器人只画一部分 | 检查实际客户端文件、缓冲指令数、模式、最后确认批次、Stamp 和控制器事件 |
| 批次发送较慢 | 大任务确认式分批存在批间等待；配置容量能够容纳的任务应根据真实缓冲计数走原来的边收边画策略 |
