# 实验验证与待评估指标

[返回总览](../README.md) · [下一章：应用展望](outlook.md)

项目已可进行从图片到机器人绘制的完整演示。方法说明需要区分代码行为、离线验证和实机实验，避免把仿真结果直接写成机器人性能结论。

## 已有验证记录

| 对象 | 已有证据 | 结论范围 |
| --- | --- | --- |
| 异常 B-spline 候选 | 228 点线条的旧候选控制点异常放大；更新后的拟合与恢复流程获得可接受的采样误差 | 验证了具体失败案例可以恢复，不代表所有线条都无误差 |
| 拟合恢复质量 | 同一诊断案例更新后记录 25 控制点，双向采样距离约 0.1406/0.1555 mm，无精确折线兜底 | 说明更新后的稳定拟合可以避免该案例整体退化为密集折线 |
| 全图路径 | 一幅示例的离线记录包括 354 条边界与 497 条填充线，最终预览及严格检查通过 | 证明该输入可生成有效计划，不等于所有画像都可无需人工调整 |
| 通信回归 | 开发阶段 27 项通信测试与 2 项朝向测试通过；包含配置容量边界、早 START、仅唤醒不重发坐标和失败停止 | 使用模拟端验证客户端逻辑，不替代控制器现场验证 |
| 大任务缓冲模拟 | 33500 条运动的合成任务通过多批发送，模拟端未丢队列指令 | 验证受控批次容量；不作为真实 ABB 丢包率或速度统计 |

上述数字来自开发记录，文档包不包含对应私人画像或全部测试工程。原工程清理后，运行目录不再保留测试文件；不能在当前运行目录直接照搬旧的 pytest 命令。需要复现实验时，应整理脱敏输入、对应版本及测试代码后单独发布。

拟合精度是几何指标，实机笔迹还受工具宽度、接触高度、纸面平整度与控制器插补影响。展示时可说明“实现了这些约束与恢复机制”，尚未测量的速度提升百分比和跨任务泛化结果应留到实验后报告。
